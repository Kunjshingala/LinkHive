Branch: main

## Problem Statement

The v1 Return Engine works: the builder shares links to LinkHive most days and
opens Today or the 9am notification often ("Loop works, I use it"). The next job
is to remove the small frictions inside that loop. The one hit most often is
**re-sharing a link already saved**. Each re-share creates a second record, because:

- `normalizeUrl()` (`lib/core/utils/validator/validator.dart:6`) only prepends
  `https://` and validates. It keeps share-tracking params (`igsh`, `si`,
  `utm_*`, `fbclid`), so the same Instagram or YouTube post shared twice gives two
  different URL strings.
- No duplicate check exists anywhere in the save path. `_saveInstantly`
  (`lib/core/services/receive_shared_intent.dart`) always writes a fresh
  `uuid.v4()` record via `LinkManager.addLink` → `LinkRepository.addLink`.

A secondary, smaller item: some cards still show a letter avatar. A favicon
fallback **already exists**:
- `lib/core/services/metadata/link_metadata_service.dart:33` tries
  `_extractIcon` (rel `icon`/`shortcut icon`), resolves relative hrefs, decodes
  entities, then falls back to `_defaultFaviconUrl` (`/favicon.ico`).
- `LinkCard._FaviconAvatar` skips SVG and uses the letter avatar on load error.

So the real gap is narrower: `apple-touch-icon` is never preferred, and the letter
avatars that remain come from causes not yet diagnosed.

## What Makes This Cool

Most apps treat a duplicate as an error: "Already saved. Save anyway?" In
LinkHive, **a re-share means you still want to read it**. So a duplicate never
warns or blocks. It merges into the original, comes back to life if it was
archived, becomes due again so Today brings it back ahead of the general pool,
and counts up: the Today
card says "Saved 3×". The duplicate turns into a useful signal instead of an error.

## Constraints

- Instant save stays one tap. No new blocking dialogs in the share flow.
- Repo conventions: BLoC sealed classes, `LinkManager` as the single entry point
  for feature blocs, `BlocListener` for side effects, `context.l10n` strings
  (en/hi/gu/ar), `printLog`, `showSnackBar`, NeoBrutalist components, FVM
  commands, `fvm flutter analyze` must be clean.
- Hive model changes need new `@HiveField` indices. 0–13 are taken, so this design
  uses 14 and 15. Both are nullable or have a `defaultValue` so legacy records decode
  (lesson from the 2026-09-24 `isQuickSaved` launch crash).
- Personal scale: hundreds to low thousands of links, so a linear scan of
  `linksBox` per save is fine.

## Premises (agreed)

1. **Match duplicates on a canonical URL, not the raw string** (rules in build
   step 1).
2. **(Revised after second opinion) A duplicate share never creates a second record and
   never blocks.** It merges into the original, reopens it if it was archived, counts the
   re-share, makes it due again, and **Undo reverts the merge's changes**. It must
   not delete; today's `onUndo` deletes by id, which would destroy the original.
3. Clipboard detect is a convenience, not a new way to save. **Deferred**.
4. Icon quality is cheap polish and secondary to the merge work.

## Cross-Model Perspective

A Claude subagent with fresh context ran the cold read (Codex is not installed).

- **Coolest version:** re-shares as a signal, with a `shareCount` +
  `lastSharedAt` "you've saved this 3 times since March" line on Today and ranking
  re-shared links higher. **Partially adopted:** `shareCount`, `lastSharedAt` and
  a plain "Saved {n}×" chip ship now. The "since {month}" copy and a shareCount-based
  ranking are **deferred** (ranking needs its own design so it doesn't beat
  least-recently-shown spreading).
- **What excites the builder:** "Loop works, I use it." Every annoyance is
  friction inside that loop.
- **50% already exists:** the ClearURLs community rules file. **Deferred.** A
  hand-written list covers v1.
- **Challenged premise #2:** found three gaps. Undo would delete the original.
  Archived links never resurface because `getResurfaceCandidate` filters
  `!isRead` (`link_repository.dart:180`, verified). Cross-device offline
  duplicates are invisible to a check at share time. The first two are fixed below;
  the third is deferred.
- **Build order:** write `canonicalUrl()` and its tests first, from the builder's
  own saved URLs. **Adopted** as the Assignment.

## Approaches Considered

- **A: Smart dedup, key computed on the fly (CHOSEN).** Effort M (human ~2
  days / CC ~1 hr), risk low.
- **B: Full canonical-identity layer** (stored key + backfill, ClearURLs
  asset, dedup when pulling from Firestore, clipboard on both platforms). Not chosen
  for now: XL effort spent on rare edge cases. It remains the clean upgrade path from A.
- **C: Deterministic ids, uuidv5(canonicalKey).** Rejected: two id schemes
  forever, and changing the rules later changes ids.

## Recommended Approach (A), build spec

### 1. URL helpers (new, pure: `lib/core/utils/url_canonical.dart`)

> **Assignment update (2026-10-07):** based on the builder's real saved links,
> **links are stored exactly as shared** (only `normalizeUrl`, as today), so
> affiliate parts (`utm_*`, `cid`, `tag`, `affid` …) survive opening, copying
> and sharing. Tracking parts are ignored **only when comparing** for duplicates.
> The old storage helper `cleanUrl` is gone; its strip rules now live inside
> `canonicalUrl`. A merge that brings a different URL keeps **both** versions
> (see §2 `otherUrls` and §6 version picker).

One function:

- **`canonicalUrl(String url) → String`** is used **only as a matching key**,
  never stored or shown. It runs `normalizeUrl` (if null, it uses the trimmed
  input), then:
  - **Strips tracking params:**
    - **Global list** (keys that mean tracking everywhere): any key starting
      `utm_`, plus `fbclid gclid gbraid wbraid msclkid ttclid twclid yclid igsh
      igshid mc_eid mc_cid _hsenc _hsmi li_fat_id srsltid`, plus the Shopify
      search keys `_pos _fid _ss _sid _psq`.
    - **Per-host list** (generic-looking keys that are only trackers on certain
      hosts):
      - `si` on YouTube hosts and `open.spotify.com`
      - `stkn` on `instagram.com` (Instagram's current share token; from the
        builder's links)
      - `ref_src` / `ref_url` on `twitter.com` / `x.com`
      - `spm` on `aliexpress.com`, `aliexpress.us`, `alibaba.com`
      - `pageUID marketplace BU fm hl_lid` on `flipkart.com` (keep `pid` =
        variant and `lid` = seller listing)

      Anywhere else these keys are kept.
    - **Host matching** for every per-host rule: lower-case the host and match
      a listed domain `d` when `host == d || host.endsWith('.' + d)`. That
      covers `www.`, `m.`, `mobile.`, `music.` and country subdomains
      (`es.aliexpress.com`). Only the TLDs listed above count; no wildcards.
  - treats `http` and `https` as the same scheme; lower-cases the host; strips
    the `www.` and `m.` prefixes; drops the trailing `/`; sorts the remaining
    query params. **An empty query is the same as no query** (`/p/X/?` ==
    `/p/X/`).
  - **Fragments:** a route-like fragment (starts with `/` or `!/`, as in a
    hash-routed app's `#/item/1`) is **kept** in the key. Only plain anchors
    (`#section-2`) are dropped. Merging two different links by mistake is worse
    than missing a duplicate.
  - **Per-host rules** (explicit, in a table):
    - YouTube (`youtube.com`, `m.youtube.com`, `music.youtube.com`, `youtu.be`):
      fold `youtu.be/X`, `/shorts/X`, `/live/X`, `/embed/X` into
      `youtube.com/watch?v=X`. **Drop** `t`, `feature`, `pp`. **Keep** `v`,
      `list`, `index`. **Never fold** `/post/X` (community posts), `/@handle`,
      `/channel/…` or `/playlist` paths; they keep their own path.
    - Instagram: **never** fold `/reel/X` with `/p/X`; path stays as-is.
    - Facebook `share/r/…`, `share/p/…` and other share short-links get a new
      code on every share, so they can't be matched without following the
      redirect. **Known limitation**: no network calls in matching.
  - **Guard:** any param on neither the global list nor a per-host drop list
    is kept. Unknown params are treated as identity.
- Cases this list doesn't settle are left to the Assignment's real-URL test set.

### 2. `LinkModel` fields

- `@HiveField(14, defaultValue: 1) int shareCount`
- `@HiveField(15) int? lastSharedAt` (UTC ms)
- **`@HiveField(16, defaultValue: <String>[]) List<String> otherUrls`**
  (Assignment update): other exact URLs of the same link, kept so the user can
  pick later. Newest last, **max 5** (oldest dropped). Add it to `copyWith`,
  `toFirestore`/`toSyncPayload` (`FirebaseConstants.linkOtherUrls`), and
  `fromFirestore` with default `[]`. Include it in the legacy-decode regression
  test (eng D8): a legacy record gives `otherUrls == []`.
- **On create** (both share and manual paths): `shareCount = 1`,
  `lastSharedAt = createdAt`.
- Add both to `copyWith`, `toSyncPayload`, Firestore (de)serialization, and
  constants in `FirebaseConstants`. **`fromFirestore` defaults `shareCount` to 1
  and `lastSharedAt` to null** when absent (legacy cloud docs).
- Run `fvm dart run build_runner build --delete-conflicting-outputs`.
- **Sync semantics:** `SyncMergeHelper` ignores both fields, so they follow
  last-writer-wins. **This is accepted.** It's one user, and the only loss is an
  increment from two devices re-sharing the same link offline at the same time
  (already deferred, see below). This is a deliberate choice, not an oversight.

### 3. Repository / manager

- `LinkRepository.findByCanonicalUrl(String url) → LinkModel?`: linear scan,
  comparing `canonicalUrl(l.url)` to `canonicalUrl(url)`. If several match
  (legacy duplicates), pick the oldest `createdAt`.
- `LinkManager.saveOrMerge(LinkModel candidate, {int? resurfaceAt, bool
  clearResurfaceAt = false}) → SaveResult`, a new method with sealed
  `SaveResult` = `Created(link)` | `Merged(merged, previous)`. `addLink` stays a
  straight delegation, matching the manager's documented "no logic in
  delegations" rule. `saveOrMerge` / `undoMerge` go in the composite-actions part
  of `LinkManager` (next to `openLink` / `archiveLink`), not under the
  "Straight delegation" banner at `link_manager.dart:60-70` (eng review CQ1).
- **Schedule input reuses the existing two-field convention** (eng review D5),
  the same `resurfaceAt` / `clearResurfaceAt` pair that `LinkModel.copyWith`
  (`link_model.dart:200-201`) and `AddLinkForm` (`add_link_state.dart:82-87`)
  already use:
  - both empty → no pick (the share path, or the form chips untouched)
  - `clearResurfaceAt: true` → Someday
  - `resurfaceAt: ms` → Tonight or Weekend
- **Serialized (eng review D6):** `LinkManager` holds one `final _saveLock =
  Lock()` from the `synchronized` package (declared as a direct dependency in
  `pubspec.yaml`; already in `pubspec.lock:1125` as a transitive one), and
  `saveOrMerge` runs inside `_saveLock.synchronized(...)`. Two quick saves of the
  same URL therefore can't both miss the match or both read the same `previous`.
  The lock gives each caller its own result or error and stays usable after a
  failure, so one failed Hive write can't break every later save.
- **Exact merge writes.** Archive and open are `markLinkAsRead` + `markResurfaced`:
  they set `isRead=true` and `lastResurfacedAt`, and clear `resurfaceAt`
  (`link_repository.dart:207,232`). So a merge writes:
  - `isRead = false`
  - `resurfaceAt`: no pick → `now` (due); `resurfaceAt: ms` → `ms`;
    `clearResurfaceAt` (Someday) → `null`, so the link rejoins the general pool
    unread but isn't due
  - `shareCount = previous.shareCount + 1`
  - `lastSharedAt = now`
  - `lastResurfacedAt` **unchanged**
  - **Writing nulls:** `LinkModel.copyWith` uses `field ?? this.field`
    (`link_model.dart:200-217`), so `null` can't be passed directly. A
    Someday merge uses the existing `clearResurfaceAt: true` flag.
  - `isQuickSaved` **unchanged** (a merge never promotes or demotes Inbox
    membership; "Add details" still promotes)
  - **Every other field is kept from the existing link**, including `url`.
    `categories` is unioned with the candidate's.
  - **`otherUrls` (Assignment update):** if the candidate's URL isn't
    byte-for-byte equal to `previous.url` or any entry in `previous.otherUrls`,
    append it (newest last, keep the last 5). `SaveResult.Merged` gets a
    `bool addedVersion` so the bar can say "Saved another version".
  - It's written via `updateLink`, so sync queues an update and no create happens.
- **`LinkManager.keepOnlyVersion(LinkModel link, String url)`** (Assignment
  update): sets `url = url`, `otherUrls = []`, then `updateLink`. It runs under
  the same `_saveLock`. Used by the version picker's "Keep only this one". The
  canonical key doesn't change, since every version shares it.
- `LinkManager.undoMerge(LinkModel previous)` reverts **only the fields the merge
  wrote** (`isRead`, `resurfaceAt`, `shareCount`, `lastSharedAt`,
  `categories`, `otherUrls`) onto the **current** record, then calls `updateLink`. Metadata
  enriched between the merge and the Undo tap (title, image, description) is
  kept. If the record is gone, it does nothing. **It runs inside the same
  `_saveLock.synchronized(...)` as `saveOrMerge`** (eng review D7), so an Undo
  and a same-link share can't interleave.
  - **Null restore:** if `previous.resurfaceAt == null` → `clearResurfaceAt:
    true` (otherwise the link would stay due after Undo). Add a new
    `clearLastSharedAt` flag to `copyWith`, same convention, for
    `previous.lastSharedAt == null` (every legacy record).

### 4. Share path (`receive_shared_intent.dart`)

- `_saveInstantly` builds the candidate with `url: normalizeUrl(url) ?? url` (as shared, Assignment update) and calls
  `saveOrMerge`. The existing try/catch that wraps `_manager.addLink`
  (`receive_shared_intent.dart:111-118`: log and bail, no "saved" snackbar on a
  Hive failure) wraps `saveOrMerge` instead, covering both branches (eng review A1).
  **On failure it shows `showSnackBar(l10n.sharedSaveFailed)`**: "Couldn't
  save this link. Try sharing again." This is a new ARB key in 4 locales,
  resolved the same null-safe, post-frame way as the merge bar (design review
  D6, 4A).
- Update the class doc comment (`receive_shared_intent.dart:22-24`, "Undo —
  deletes it") to describe both outcomes: Undo deletes a new link, and reverts a
  merge (eng review CQ2).
- **Localize the non-URL share message (eng review D10):** replace the
  hardcoded `'Only URL links can be saved to LinkHive'` at
  `receive_shared_intent.dart:74,90` with a new ARB key `sharedOnlyUrls` (all 4
  locales). Resolve it through `scaffoldMessengerKey.currentContext`,
  null-checked, with an English fallback like `LinkManager._couldNotOpen`.
  - `Created`: today's behavior (snackbar, background enrich).
  - `Merged`: the merge snackbar (step 6) with **Add details** (opens the merged
    link, same as today) and **Undo** → `undoMerge(previous)`. Background
    enrichment runs only if the merged link's title is still empty.
- **Cold-start redelivery:** with dedup in place, a redelivered initial share
  would show up as a re-share (`shareCount++`). Check on device whether
  `getInitialMedia` redelivers after the share is handled. If it does, call
  `ReceiveSharingIntent.instance.reset()` after handling it.

### 5. Manual Add (`AddLinkBloc` add mode)

- Stores `normalizeUrl(url)` as today (no stripping, Assignment update). Save calls `saveOrMerge` passing the form's existing
  `resurfaceAt` / `clearResurfaceAt` pair straight through (no conversion). **An
  explicit pick, Someday included, beats `now`.**
- **A manual-add merge keeps every existing field** (title, description, image,
  priority) and only unions categories. AddLinkForm cannot tell typed values from
  fetched ones or defaults, so overwriting would clobber a curated title or High
  priority with fetched text or the default Normal.
- **Telling the user their typed details weren't applied:** the manual-merge
  snackbar uses its own copy, `addAlreadySavedKept`: "Already saved {date}.
  Kept your existing details." So dropping the form input is stated, not
  silent.
- **State:** `AddLinkSuccess` is **unchanged** (edit mode and add-Created still
  emit it). Add mode emits a **new `AddLinkMerged(merged, previous)` state**
  when the result is `Merged`. The `AddLinkScreen` `BlocListener`:
  - `AddLinkSuccess` → pop (as today, both modes).
  - `AddLinkMerged` → pop, then show the manual-merge snackbar with **[Edit]**
    and **[Undo]** (design review D7, 5A). Edit uses the existing
    `linkEditLabel` key ("Edit") and calls
    `router.pushNamed(MyRouteName.editLink, extra: manager.linkById(merged.id) ?? merged)` (re-read, like `receive_shared_intent.dart:131`; eng re-review A2) through the global
    router, because the form has already closed. Undo → `undoMerge(previous)`.
    There's no "Add details": the user just came from the form, and Edit covers it.
  - **The Undo callback calls `locator<LinkManager>().undoMerge(previous)`
    directly**, captured before the pop. It never goes through `AddLinkBloc`,
    because that bloc is closed once the screen is disposed and the snackbar
    outlives it.
- Edit mode is unchanged. Editing a URL to match another link is not deduplicated
  (out of scope).

### 6. Merge snackbar + l10n

- Extend `showSavedLinkSnackBar` with an optional `String? message` (default
  stays `sharedSaveConfirm`) and an optional `onAddDetails` (null hides that
  button).
- **Layout (design review D3, 1A):**
  - **Fresh save** (`message == null`): today's one-row layout, unchanged.
  - **Merge** (`message != null`): a `Column`. The top row is the icon plus the
    message in an `Expanded` `Text` (`maxLines: 3`, ellipsis only as a last
    resort). The bottom row holds the actions (Add details if given, then Undo),
    aligned with `MainAxisAlignment.end`, so the order flips correctly in RTL
    Arabic. `AppSpacing.sm` between the rows.
  - Duration: 5s for a fresh save (unchanged), **8s for a merge**, since a date
    plus Undo needs more reading time.
- **Touch targets (design review D13, 13A):** in **both** bars, the Add
  details / Edit / Undo buttons go from `height: 40` to `height: 44`
  (`saved_link_snackbar.dart:91,98`), and the icon-only Undo gets a 44×44
  minimum. The fresh-save bar grows 4dp; that change is accepted.
- **Merge icon (design review D4, 2A):** a merge shows `Icons.history_rounded` in
  `AppColors.black` on a 32dp circle filled `AppColors.accentPurple` with a 2px

  `AppColors.success`. The fill and icon colors are fixed in both themes, the
  same rule `PriorityBadge` uses for pastel fills, so the icon stays readable in
  dark mode.

- New ARB key `sharedAlreadySaved`: "Already saved {date}, it'll come back in
  Today". The copy promises "it'll come back", not "it's next": the link is
  due, but older due links are picked first (step 7). It also avoids "moved up",
  because Home and Inbox sort by `createdAt` and the link doesn't move there.
- `{date}` = the **original link's `createdAt`**, declared in the ARB as a
  `DateTime` placeholder with `"format": "yMMMd"`, so `gen-l10n` formats it for
  the active locale. It's passed as **local time**:
  `DateTime.fromMillisecondsSinceEpoch(createdAt)` (not `isUtc: true`), so an IST
  save at 00:30 doesn't show the previous day.
- **Which message (eng re-review D18):** `_saveInstantly` gets the bar text from a public pure `shareOutcomeMessage(result, error, l10n, now)` in `lib/core/services/share_feedback.dart` (fresh / already saved / unarchived / failed), unit-tested in `test/core/services/share_feedback_test.dart`.
- **Where the string is built:** the share path has no `BuildContext`. It
  reads `scaffoldMessengerKey.currentContext`, **null-checked, never
  force-unwrapped** (the same pattern as `LinkManager._couldNotOpen`,
  `link_manager.dart:188-191`). If it's null (a cold-start share arriving before the
  messenger mounts), **it waits for the first frame**
  (`WidgetsBinding.instance.addPostFrameCallback`) and then builds and shows the
  same bar, for both fresh saves and merges (design review D5, 3A). If the
  context is still null after that frame, it skips the bar. The merge is already
  written either way. Otherwise it builds the string and passes it as
  `message`. The manual path builds it in the `BlocListener` from its own
  context.
- **Date wording (design review D9, 7A), which replaces the `DateTime`/`yMMMd`
  placeholder above for all three keys:** `{date}` becomes a **`String`**
  placeholder filled by a small formatter (`formatSavedDate(DateTime local,
  DateTime now, Locale)` in `lib/core/utils/`):
  - same calendar day → "today" (new ARB key `dateToday`)
  - previous day → "yesterday" (new key `dateYesterday`)
  - same year → `DateFormat.MMMd(locale)` ("Sep 28")
  - older → `DateFormat.yMMMd(locale)` ("Sep 28, 2025")

  Copy is written so both forms read naturally: "Already saved {date}", and
  `sharedUnarchived` becomes "You archived this {date}, it'll come back in Today"
  (no "on", so "today" reads correctly). Translators get the same constraint
  through an ARB `@` description. Add table tests for the formatter (call `initializeDateFormatting()` in `setUpAll` for hi/gu/ar symbols, eng re-review CQ3; cases: today,
  yesterday, same year, previous year, local midnight in IST).
- New ARB key `addAlreadySavedKept` (`{date}`, same String placeholder), used by
  the manual-merge snackbar (step 5).
- **Screen name in the copy (design review D11, 11A):** in the hi/gu/ar values
  of `sharedAlreadySaved` and `sharedUnarchived`, write the Today screen name
  exactly as each locale's existing `todayTitle` (`app_hi.arb:56` "आज",
  `app_gu.arb:56` "આજે", `app_ar.arb:56` "اليوم"). Add an `@`-description
  telling translators to keep it in sync with `todayTitle`.
- **New ARB key `sharedUnarchived` (design review D8, 6A):** "You archived this
  {date}, it'll come back in Today" (wording per D9). The share-path merge bar uses it when
  `previous.isRead == true`; unread links keep `sharedAlreadySaved`.
  - `{date}` = `previous.lastResurfacedAt ?? previous.createdAt`, in local time.
    Archive and Open both call `markResurfaced`, so `lastResurfacedAt` is
    roughly when the link was finished.
  - Note: `isRead` is set by Open as well as Archive (`LinkManager._recordConsumed`).
    So "archived" also describes links the user opened and read. Accepted as the
    approved wording, and flagged for the copy check on device.
- New ARB key `todaySavedCount`: an ICU plural, "Saved {count}×".
- **Assignment update, two-version copy and picker:**
  - New ARB key `sharedAnotherVersion`: "Saved another version of this link,
    it'll come back in Today" (with each locale's `todayTitle`). Message
    precedence in `shareOutcomeMessage`: error → `sharedSaveFailed`; Merged with
    `addedVersion` → `sharedAnotherVersion`; Merged with `previous.isRead` →
    `sharedUnarchived`; Merged → `sharedAlreadySaved`; Created →
    `sharedSaveConfirm`.
  - **Version picker** (new `lib/sharedWidgets/version_picker_sheet.dart`, a
    standard bottom sheet per the "never AlertDialog" rule). When a link has
    `otherUrls.isNotEmpty`, every **Open** surface shows it first: Today's
    Open button, `LinkCard` tap, and Home's Up Next. A widget tap opens Today,
    so it's covered too.
    - Rows: the main URL first, then `otherUrls`. Each shows the host and path
      plus a short line of its query keys (e.g. `utm_source · cid`), or "no
      tracking" when there are none. Radio selection; the main URL is
      preselected.
    - Actions: **[Open]** → `LinkManager.openLink(link, url: chosen)` (same
      record-then-launch order; `openLink` gains an optional `url`);
      **[Keep only this one]** → `keepOnlyVersion(link, chosen)`, then open.
    - New ARB keys: `versionPickerTitle` ("Which version?"),
      `versionPickerNoTracking` ("no tracking"), `versionPickerKeepOnly` ("Keep
      only this one"); reuse `todayOpen` for Open.
    - A link with no other versions opens directly, exactly as today.
